### 1. 用户登录接口文档  
**接口路径**：`/api/v1/user/login`  
**请求方法**：`POST`  
**认证类型**：`public`  
**支持方法**：`POST`, `OPTIONS`  
**CSRF保护**：禁用 (`csrf=False`)  

---

#### 功能描述  
提供用户登录认证服务，验证用户凭证后：  
1. 创建/更新用户会话并存储到数据库  
2. 返回会话ID、用户角色和地理位置信息  
3. 支持跨域请求 (CORS)  

---

#### 请求参数 (JSON格式)  
| 参数名     | 类型   | 必填 | 说明                 | 示例值          |  
|------------|--------|------|----------------------|-----------------|  
| `db`       | string | 是   | 数据库名称           | "oak_production"|  
| `login`    | string | 是   | 用户登录账号 (邮箱)  | "admin@oak.com" |  
| `password` | string | 是   | 用户密码             | "secure123"     |  

**请求示例**：  
```json
{
  "db": "oak_production",
  "login": "admin@oak.com",
  "password": "secure123"
}
```

---

#### 响应结构  
**成功响应 (HTTP 200)**  
```json
{
  "status": 200,
  "msg": "登录成功",
  "data": {
    "user_id": 2,
    "session_id": "a1b2c3d4e5f6",
    "user_roles": ["project_owner"],
    "geo_latitude": "31.2304",
    "geo_longitude": "121.4737",
    "geo_zoom_ratio": "10.0"
  }
}
```

**字段说明**：  
| 字段             | 类型     | 说明                          |  
|------------------|----------|-------------------------------|  
| `user_id`        | int      | 用户唯一ID                    |  
| `session_id`     | string   | 会话ID (后续请求需携带)       |  
| `user_roles`     | string[] | 用户角色列表                  |  
| `geo_latitude`   | string   | 用户最后已知纬度坐标          |  
| `geo_longitude`  | string   | 用户最后已知经度坐标          |  
| `geo_zoom_ratio` | string   | 地图缩放比例                  |  

> **角色说明**：  
> - `project_owner`: 项目负责人 (可访问所有数据)  
> - `water_supplier`: 供水服务商 (仅访问自身数据)  

---

#### 错误响应  
**HTTP 400 - 参数缺失**  
```json
{
  "status": 400,
  "msg": "Missing database parameter",
  "success": false
}
```

**HTTP 401 - 认证失败**  
```json
{
  "status": 401,
  "msg": "Authentication failed",
  "success": false
}
```

**HTTP 500 - 系统错误**  
```json
{
  "status": 500,
  "msg": "Login failed",
  "error": "Database connection error"
}
```

---

#### 技术实现细节  
1. **会话存储**  
   - 会话信息存储到 `ir_session` 数据库表  
   - 会话有效期：24小时  
   - 表结构自动创建（如不存在）  

2. **安全机制**  
   - 会话ID格式验证：`/^[a-zA-Z0-9_-]+$/`  
   - 密码传输需加密 (HTTPS)  
   - 响应头包含严格CORS策略：  
     ```http
     Access-Control-Allow-Origin: *
     Access-Control-Allow-Credentials: true
     ```

3. **数据处理流程**  
   ```mermaid
   graph TD
     A[接收请求] --> B{OPTIONS请求?}
     B -->|是| C[返回CORS头]
     B -->|否| D[验证数据库参数]
     D --> E[调用父类登录逻辑]
     E --> F{登录成功?}
     F -->|是| G[保存会话到数据库]
     G --> H[添加角色/位置信息]
     H --> I[返回增强响应]
     F -->|否| J[返回错误信息]
   ```

---

#### 开发者注意事项  
1. **会话使用**：  
   后续请求需在Header中携带会话ID：  
   ```http
   Authorization: Bearer {session_id}
   ```

2. **数据库要求**：  
   确保数据库存在 `ir_session` 表结构，字段包括：  
   - `sid` (会话ID)  
   - `uid` (用户ID)  
   - `db` (数据库名)  
   - `write_date` (最后更新时间)  

3. **性能优化**：  
   - 高频登录场景建议添加Redis缓存层  
   - 会话查询已添加索引优化 (`ir_session_sid_idx`)  

4. **监控指标**：  
   - 日志关键字：`用户登录成功` / `登录处理错误`  
   - 关键指标：登录成功率、平均响应时间  



### 2. 用户位置更新接口文档  
**接口路径**：`/api/v1/user/update`  
**请求方法**：`POST`  
**认证类型**：`public`  
**支持方法**：`POST`, `OPTIONS`  
**CSRF保护**：禁用 (`csrf=False`)  

---

#### 功能描述  
更新登录用户的地理位置信息（纬度、经度、地图缩放比例），适用于移动端实时位置同步场景。  

---

#### 请求参数 (JSON格式)  
| 参数名            | 类型    | 必填 | 说明                      | 示例值       |  
|-------------------|---------|------|---------------------------|-------------|  
| `session_id`      | string  | 是   | 用户会话ID                | "a1b2c3d4e5"|  
| `geo_latitude`    | float   | 是   | 纬度坐标                  | 31.2304     |  
| `geo_longitude`   | float   | 是   | 经度坐标                  | 121.4737    |  
| `geo_zoom_ratio`  | float   | 是   | 地图缩放比例              | 10.0        |  

**请求示例**：  
```json
{
  "session_id": "a1b2c3d4e5",
  "geo_latitude": 31.2304,
  "geo_longitude": 121.4737,
  "geo_zoom_ratio": 10.0
}
```

---

#### 响应结构  
**成功响应 (HTTP 200)**  
```json
{
  "status": 200,
  "msg": "位置信息更新成功",
  "success": true
}
```

**错误响应**  
| HTTP状态码 | 错误类型              | 响应示例                                |  
|------------|-----------------------|----------------------------------------|  
| 400        | 参数缺失/格式错误     | `{"status":400,"msg":"缺少必要参数: geo_latitude","success":false}` |  
| 401        | 会话无效/过期         | `{"status":401,"msg":"用户未认证或会话已过期","success":false}` |  
| 404        | 用户不存在            | `{"status":404,"msg":"用户不存在","success":false}` |  
| 500        | 系统错误              | `{"status":500,"msg":"位置信息更新失败","error":"...","success":false}` |  

---

#### 技术实现细节  
1. **安全验证**  
   - 会话ID格式验证：`/^[a-zA-Z0-9_-]+$/`  
   - 会话有效期：24小时  
   - 用户状态检查：仅更新活跃用户  

2. **数据处理**  
   ```mermaid
   graph LR
     A[接收请求] --> B{OPTIONS预检?}
     B -->|是| C[返回CORS头]
     B -->|否| D[解析JSON参数]
     D --> E[验证会话ID]
     E --> F{会话有效?}
     F -->|否| G[返回401错误]
     F -->|是| H[获取用户对象]
     H --> I[转换坐标值为浮点数]
     I --> J[更新用户位置字段]
     J --> K[返回成功响应]
   ```

3. **数据库操作**  
   更新`res_users`表字段：  
   - `latitude` → 存储`geo_latitude`  
   - `longitude` → 存储`geo_longitude`  
   - `ratio` → 存储`geo_zoom_ratio`  

4. **容错机制**  
   - 非数值坐标自动转为0.0  
   - 空值处理：保留原值不更新  
   - 错误日志记录完整堆栈跟踪  

---

#### 开发者注意事项  
1. **会话要求**  
   - 需先通过`/api/v1/user/login`获取有效`session_id`  
   - 请求头需携带：  
     ```http
     Authorization: Bearer {session_id}
     ```

2. **移动端集成**  
   ```javascript
   // JavaScript调用示例
   async function updateLocation(lat, lng, zoom) {
     const response = await fetch('/api/v1/user/update', {
       method: 'POST',
       headers: {'Content-Type': 'application/json'},
       body: JSON.stringify({
         session_id: getSessionID(),
         geo_latitude: lat,
         geo_longitude: lng,
         geo_zoom_ratio: zoom
       })
     });
     return response.json();
   }
   ```

3. **性能指标**  
   | 指标                | 预期值       |  
   |---------------------|-------------|  
   | 平均响应时间        | < 300ms     |  
   | 并发处理能力        | 1000+ req/s |  
   | 错误率              | < 0.5%      |  

> **定位频率建议**：移动端推荐5-10分钟更新一次，避免频繁请求
