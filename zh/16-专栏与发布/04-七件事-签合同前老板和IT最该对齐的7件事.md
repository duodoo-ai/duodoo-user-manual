**标题：【七件事】签合同前，老板和 IT 最该对齐的 7 件事**

> 专栏「工贸 ERP · 分期与验收」第 4 篇 · 2026-10 发布  
> 第 01 篇：[干了19年IT…](./01-干了19年IT-我看透了ERP一期烂尾的真相.md) · 第 02 篇：[【边界】…](./02-边界-一期塞太多不是省钱是烂尾的开始.md) · 第 03 篇：[【分期表】…](./03-分期表-制造贸易ERP一张表划清一期和二期.md)

分期表划完，还差 **签字依据**。下面七条，每条对应 **合同附件、纪要或验收包里的一个文件**；某友、某蝶、Odoo 通用。  
建议用法：立项或合同谈判前，IT 与老板过一遍打勾；实施中期每月例会只对照 **③④⑤**；验收前两周集中收口 **⑥**。

### 打勾单解决什么问题

群里争「算不算一期」，本质是 **没有附件里的终点**。打勾单给 IT 三样东西：**开会议程、乙方交付对照表、老板签字前的自检**。  
乙方 PM 也可拿这份清单反向自检：哪些交付物还没齐，别等最后一天才补签字页。甲方最怕的不是功能少做，而是 **做了但无法证明做过**。

### ① 范围书面化

| 必须落地 | 说明 |
|----------|------|
| 附件名称 | 建议固定叫《一期范围及模块清单》《二期范围及触发条件》（可合并为一册两章） |
| 确认方式 | 合同签字页引用附件编号，或双方授权邮箱 **回复确认**（保留邮件） |
| 变更 | 单独《范围变更记录》：日期、提出人、影响模块、工期/费用是否调整 |

**与分期表**：[第 3 篇【分期表】](./03-分期表-制造贸易ERP一张表划清一期和二期.md) 填完后 **整表或等价清单进附件**，不是 PPT 截图。清单里每一行模块，后面加一列 **「一期验收标准」**（一句话即可），例如「销售订单可下单、出库、生成应收」——避免 UAT 时临时抬标准。  
**反例**：合同只写「实施 ERP」——UAT 周五部门各掏需求，项目没有终点。  
**实务**：范围附件版本号随变更递增（V1.0、V1.1），邮件确认写「同意按附件 V1.1 执行一期范围」。

### ② 主数据

| 字段写进附件 | 示例 |
|--------------|------|
| 责任人 | 物料：张三（录）/ 李四（审）；客户、供应商同理 |
| 截止日 | 如「2026-04-30 前完成历史清洗，之后新增只在系统维护」 |
| 签收 | 《主数据导入签收》：导入批号、条数、已知例外 N 条及责任人 |

**干货**：编码规则（沿用旧码 / 统一重编）写一句；否则上线后三个月还在改客户名称后缀。  
**常见坑**：同一物料多个旧码未合并、计量单位不一致、客户同名不同信用额度——导入前用 **例外清单** 列明「暂不合并、原因、责任人」，比假装一次导干净更诚实。  
主数据截止日后 **冻结线下新建**：新物料、新客户只能在系统申请，否则双轨永远关不上。

### ③ 第一个「只信系统」的账期

| 必须写清 | 说明 |
|----------|------|
| 账期 | 如「自 2026 年 5 月关账起，损益类调整须有系统单据」 |
| 例外 | 哪些仍允许 Excel（最好写「无」或列明 1～2 类临时例外及截止日） |
| 双轨红灯 | 并行常超过 **3～4 个月** 时，数据与士气双崩——纪要里写并行截止日 |

财务和老板 **同会签字** 这一条，不要留给「上线后再说」。  
并行期内建议 **每周一次** 系统账与 Excel 调节表对照（哪怕只有关键科目），差异超过阈值必须查单号，别累积到月底。运费、返利、汇差若长期手工改，要在③里写明 **逐步迁入系统的截止阶段**，否则财务永远有理由不签字。

### ④ 权限与关键流程演练

**最少跑通的路径**（一期验收建议全覆盖，可增不可减）：

| 场景 | 验收时至少保留 |
|------|----------------|
| 销售到收款 | 报价/订单 → 发货或确认 → 开票/应收 → 收款核销（测 1 个完整单号） |
| 采购到付款 | 请购/PO → 收货 → 应付 → 付款（测 1 个完整单号） |
| 库存 | 入库、出库、盘点调整各 1 笔（有仓则必测） |
| 权限 | 《岗位权限矩阵》与系统角色一致；离职/调岗有禁用记录 |

交付物：**演练签到或测试单号列表**，不是培训签到代替流程测试。  
**建议加测**：负向权限——普通仓管不能改价、销售不能自己核销应收等，抽 2～3 个岗位试「故意越权应被拒绝」。  
有审批流时，留 **同一单据从创建到结束的状态截图或日志编号**，验收争议时比口头描述管用。出海项目把财务必验链路单独列在 UAT 表一行（细节见 [【边界】](./02-边界-一期塞太多不是省钱是烂尾的开始.md)）。

### ⑤ 并行期上限

纪要或合同写：**双轨最长 N 月**（常见 2～3，上限不宜超过 4），到期后：

- 新业务单据 **只接受系统录入**；或  
- 未切换部门由 **分管副总书面延期**（每次延期重新签字）。

没有上限，业务会永久「先 Excel 一下」。  
并行结束前两周，IT 出 **切换检查表**：哪些报表已只用系统出、哪些部门仍有线下台账、未切换原因与计划日——老板一眼能看出是谁在拖。

### ⑥ 验收交什么

**一期验收包建议目录**（乙方打包交付，甲方归档）：

1. 已签署的《一期范围》及变更记录（如有）  
2. UAT 用例 + **执行结果**（通过/失败/遗留编号）  
3. 《遗留问题清单》：编号、描述、是否阻碍一期关闭、计划关闭日  
4. 《一期验收签字页》（见下表）  
5. 培训记录（辅助，**不能替代** UAT）

| 签字页字段 | 内容 |
|------------|------|
| 验收范围 | 引用附件模块列表 |
| 遗留问题 | 列出编号；注明「不阻碍一期关闭」须财务书面认可 |
| 签字 | 业务负责人、财务、IT、乙方 PM；日期 |

**分清**：UAT 通过 = 用例执行完；**一期关闭** = 财务认可关账口径 + 签字页齐。  
遗留问题建议分 **阻碍关闭 / 不阻碍关闭** 两类：不阻碍的也要写计划关闭日，避免「永久遗留」。乙方要求「先签字再改」时，甲方可以签 **有条件通过**：签字页注明遗留编号与承诺日期。  
培训记录只证明「讲过」，不能代替④里的 **单号级演练**。

### ⑦ 二期触发条件

写进附件或纪要，避免「快上了」：

| 触发条件（示例，择一或多条） | 说明 |
|------------------------------|------|
| 生产 | 连续 N 月量产且 BOM 变更率低于约定阈值 |
| 财务 | 国内主体连续 M 月按③关账无重大调整 |
| 组织 | 海外法人 **单独立项**，不绑国内一期签字 |

一期内新需求：**变更记录** 或 **等二期范围会**，禁止验收前口头加模块。  
销售在验收前承诺的「小功能」也要走变更——否则二期预算永远被一期吃掉。触发条件尽量 **可观测**（产量、关账月数、签字主体），少写「业务稳定后」这种无法举证的话。

### 合同句式（方向性，非律师意见）

1. **验收**：「一期验收以附件《一期范围及 UAT 清单》为准；乙方交付测试记录、遗留问题清单及签字页；甲方财务对关账口径的书面确认为一期验收必要条件。」  
2. **变更**：「范围变更须书面确认并调整工期或费用；未确认功能不纳入一期验收。」  
3. **可选 · 并行**：「双方约定并行期不超过 N 个月；期满新业务单据以系统为准，除非甲方书面延期。」

### 验收会建议顺序（IT 主持可参考）

1. 对照附件范围，确认本期不扩模块  
2. 过 UAT 执行结果与遗留清单  
3. 财务确认③关账口径是否已执行至少一个账期  
4. 各方在签字页签字；二期只讨论 **触发条件是否满足**，不现场加需求
