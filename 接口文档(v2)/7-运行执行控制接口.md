# 设备控制日志API接口文档

## 概述

本文档详细描述了设备控制日志API接口的使用方法和参数说明。所有接口都遵循RESTful设计原则，使用JSON格式进行数据交换，支持Bearer Token身份认证。

### 基础信息

- **基础URL**: `/api/v2/control/log`
- **认证方式**: Bearer Token (格式: `Bearer session_id` 或 `Bearer db_name.session_id`)
- **内容类型**: `application/json`
- **字符编码**: UTF-8
- **CORS支持**: 所有接口都支持跨域请求

### 接口列表

| 接口名称 | 方法 | 路径 | 描述 |
|---------|------|------|------|
| 获取日志列表 | GET | `/api/v2/control/log/list` | 获取控制日志列表，支持分页和筛选 |
| 获取日志详情 | GET | `/api/v2/control/log/detail/<log_id>` | 获取单个控制日志的详细信息 |
| 获取日志统计 | GET | `/api/v2/control/log/stats` | 获取控制日志的统计信息 |
| 标记操作成功 | POST | `/api/v2/control/log/<log_id>/mark-success` | 标记控制日志为成功 |
| 标记操作失败 | POST | `/api/v2/control/log/<log_id>/mark-failed` | 标记控制日志为失败 |
| 重试操作 | POST | `/api/v2/control/log/<log_id>/retry` | 重试控制日志操作 |
| 获取日志概览 | GET | `/api/v2/control/log/overview` | 获取控制日志概览信息（仪表板用） |
| 创建日志记录 | POST | `/api/v2/control/log/create` | 创建新的控制日志记录 |

## 接口详细说明

### 1. 获取控制日志列表

#### 接口信息
- **方法**: GET
- **路径**: `/api/v2/control/log/list`
- **描述**: 获取控制日志列表，支持分页、筛选和排序

#### 请求参数

**Query Parameters:**

| 参数名 | 类型 | 必填 | 默认值 | 描述 |
|--------|------|------|--------|------|
| page | int | 否 | 1 | 页码 |
| limit | int | 否 | 20 | 每页记录数 |
| operation_type | string | 否 | - | 操作类型筛选，逗号分隔（start,stop,pause,resume,mode_change,parameter_adjust） |
| operation_target | string | 否 | - | 操作目标筛选，逗号分隔（project,pipeline,pump_station,pump） |
| operation_result | string | 否 | - | 操作结果筛选，逗号分隔（success,failed,pending,partial） |
| project_id | int | 否 | - | 项目ID筛选 |
| pipeline_id | int | 否 | - | 管线ID筛选 |
| pump_station_id | int | 否 | - | 泵站ID筛选 |
| equipment_id | int | 否 | - | 设备ID筛选 |
| operator_id | int | 否 | - | 操作者ID筛选 |
| is_scheduled | boolean | 否 | - | 是否调度操作 |
| requires_followup | boolean | 否 | - | 是否需要跟进 |
| is_retried | boolean | 否 | - | 是否重试操作 |
| date_from | string | 否 | - | 操作开始日期，格式：YYYY-MM-DD |
| date_to | string | 否 | - | 操作结束日期，格式：YYYY-MM-DD |
| completion_date_from | string | 否 | - | 完成开始日期，格式：YYYY-MM-DD |
| completion_date_to | string | 否 | - | 完成结束日期，格式：YYYY-MM-DD |
| log_reference | string | 否 | - | 日志编号模糊搜索 |
| operation_reference | string | 否 | - | 操作参考模糊搜索 |
| order_by | string | 否 | operation_date desc | 排序字段，格式：field_name asc/desc |

## 错误处理

### 错误码说明

| 状态码 | 含义 | 说明 |
|--------|------|------|
| 200 | OK | 请求成功 |
| 201 | Created | 资源创建成功 |
| 400 | Bad Request | 请求参数错误 |
| 401 | Unauthorized | 身份认证失败 |
| 404 | Not Found | 资源不存在 |
| 500 | Internal Server Error | 服务器内部错误 |

### 错误响应格式

所有错误响应都遵循以下格式：

```json
{
    "status": 错误码,
    "msg": "错误描述",
    "success": false
}
```

## 认证方式

所有API接口都需要Bearer Token认证。Token需要包含在请求头中：

```
Authorization: Bearer <session_id>
```

或者带数据库前缀：

```
Authorization: Bearer <db_name>.<session_id>
```

## 性能优化建议

### 1. 查询优化
- 使用合适的筛选条件缩小查询范围
- 避免使用模糊搜索作为主要筛选条件
- 合理使用索引字段进行排序

- 只请求需要的字段（通过筛选条件控制）
- 使用分页控制返回数据量
- 对于大量数据，考虑使用流式返回

- 对于不经常变动的数据（如项目列表、操作者列表）可以适当缓存
- 统计信息可以定时计算缓存

### 4. 异步处理
- 对于耗时的操作（如大量数据导出），考虑使用异步任务处理
- 使用消息队列处理高并发请求
