**标题：【工贸 ERP · 分期与验收】干了19年IT，从长三角工贸到沙特工厂，我看透了ERP一期烂尾的真相**

> 专栏「工贸 ERP · 分期与验收」· 合订篇 · 2026-10 发布（知乎 / CSDN）

前阵子刚从沙特回国。在那边的工厂，我们刚把一期ERP的进销存、基础财务、人事考勤跑通，UAT顺利验收。为了不把制造模块硬塞进一期，我们在现场跟总部、业务线扛了很久的压力。

回到南京，一个做加工贸易的老乡找我诉苦。他买了个老牌年费ERP（某友/某蝶这类），每年交着不菲的年费，结果销售、财务、仓库三家账永远对不上。想换开源Odoo，又怕再上一家还是烂尾。

我问他：“合同里的‘一期验收’，到底验什么？”
他答不上来。

其实，无论国内几十万上百万的买断大厂系统，还是我实操的开源Odoo，烂尾的根源从来不在软件。**“一期”这两个字，不同岗位的人脑子里装的算盘不同，这就是灾难的开始。**

作为在乙方交过代码、在甲方背过锅、现在又在沙特前线做交付的人，我见过太多离谱的场面：

老板一句“一期全包”，销售为了签单满口答应。生产说要上MES，财务说要搞复杂成本核算，人事说要立刻上绩效。最后全塞进第一期范围里，UAT排了五轮，各部门互相踢皮球，没人敢签字。

系统上线了，财务还在Excel里改运费、调返利。三个月后数据对不上，老板拍桌子说“系统不行”——其实是合同里从来没写清楚：从哪天开始，只认系统里的账。

很多IT夹在中间两头受气，是因为合同里只有“上线”两个字，没有测试用例、没有签字页，只有微信群里一句“先跑起来看看”。

### 一、为什么“分期”这件事，必须写进合同

我在华东一家机电工贸企业做信息负责人的时候，吃过这种亏。那时候我们要上WMS和轻MES，销售、生产、仓库全搅在一起。后来我学乖了：**所有口头承诺，都必须拉一张分期清单，邮件确认或者签附件。**

分期从来不是“买少点模块”那么简单。分期是**把“范围、两套账、全员习惯”这三颗雷，分开来爆。**

千万别指望“一期全包”能省钱。把MES和复杂成本核算塞进一期，不仅上线遥遥无期，还会把原本能跑通的进销存拖死。先能关账、能跑单，再谈精细化管理，这是铁律。

### 二、真实案例：人事考勤，怎么被硬生生塞进一期

这次在沙特工厂，我们的一期范围定得很死：进销存、基础财务、人事考勤。制造深度、复杂成本全部书面押后到二期。

很多人觉得人事考勤是个边缘模块，其实在出海工厂，考勤是关账的大头。

我们现场遇到的最大障碍是：当地的考勤机是老旧系统，是个彻底的异构系统，没有标准API，导出来的数据格式乱七八糟。总部要求必须把出勤数据打通到Odoo，否则人事没法算工资，月底就关不了账。

当时摆在我面前的有两条路：一是让公司花大价钱买一套现成的考勤中间件，二是自己动手。

我选了第二条。写了一段本地代码，直接从考勤机的底层数据库里把打卡记录抠出来，做清洗、去重、匹配班次，然后精准地推入Odoo的attendance模块。

那段代码调试得很痛苦，经常要在现场测试到深夜。但结果是好的：异地的管理团队在中控室就能看到实时的出勤数据，人事月底直接一键算薪。**这就是IT老兵的底线——系统能不能跑通，不看PPT，看代码。**

国内很多纯贸易或者轻加工的企业，道理是一样的。一期验的是“经营账能关、主流程能跑、人员能管”，不是把三年的数字化规划全塞进半年里。

### 三、一张表：建议一期、二期边界怎么划

我打印给老板们看的一张表（制造 + 贸易，含轻加工）。纯贸易的可以只看前三行；有车间的，重点看后面几行。

| 能力模块 | 建议一期 | 建议二期 | 备注（为什么） |
|----------|:--------:|:--------:|------|
| 进销存 / 采购销售流程 | ✅ | | 先能关账 |
| 基础财务 / 应收应付 | ✅ | | 别和进销存两套账 |
| 主数据（物料、客户、供应商） | ✅ | | 谁录入、谁审核，写名字 |
| 人事考勤 / 异构数据采集 | ✅ | | 现场设备打通，算薪基础 |
| 生产订单 / MES / 车间 | | ✅ | 制造深度，依赖产线稳定 |
| 成本核算 / 标准成本 | | ✅ | 生产稳了再上 |
| 跨境多法人 / 当地开票 | 视企业 | ✅ 常见 | 合规路径单独谈 |
| 设备数采 / 大屏 | | ✅ | 别和 ERP 绑在一期里 |

开源 ERP、某友、某蝶，**玩法都一样**：先划一期二期，再谈人天。指望“一期全包”省钱的，后面往往更贵。我经历过太多血的教训，原本三四十万能跑通的一期，因为硬塞了不成熟的模块，最后追加了上百万的二次开发费，项目还烂尾了。这不是软件的问题，是项目的边界管理出了大问题。

### 四、出海那家，当时怎么定的（脱敏）

某制造基地在海外开工，国内总部催进度。我们当时咬死一条：**本期签字只认进销存 + 基础财务 + 人事考勤 + 相关部门 UAT 通过**；制造深度、成本核算写在二期附件里，谁也别在验收前塞功能。

上线前夜做备份，升版窗口钉在周末，国内远程、现场同事分工写在一张待办上。为了考勤的准确性，我在现场连着几个晚上和车间主任核对班次逻辑，确保每一笔打卡记录都能准确对应到Odoo的出勤状态。

不花哨，但**验收那天有纸可签**。国内工厂不用出海，道理一样：一期验的是“账能关、人可控”，不是把三年规划塞进六个月。

### 五、签合同前，我会让老板和 IT 对一下这七行

不用背，打印出来打勾就行。

1. **一期、二期清单**有没有附件？邮件确认也行，别只停留在口头。
2. **主数据**谁洗历史、谁终审，截止日期是哪一天。主数据不干净，系统就是垃圾场。
3. **几月停 Excel**——第一个“只信系统”的账期写清楚，这是推脱不掉的硬指标。
4. **权限 + 演练**：采购到付款、销售到收款，关键岗至少走过一遍，别让员工上线那天才第一次摸系统。
5. **并行别拖太久**；我见过的，双轨超过三四个月，项目气氛就会坏掉，两边都疲于奔命。
6. **验收交什么**：用例、遗留问题、签字页，不是“感觉能用”。没签字，IT就得背锅。
7. **什么时候才该谈二期**——比如产线稳定量产了，再开范围会，别一期里偷偷加。

IT 把这张纸甩给老板，比在微信里争“这个模块算不算一期”省事。

### 六、开源 Odoo 与“标品 + 个性”的防烂尾逻辑

很多人问我，为什么不用大厂的标准软件，而是选开源 Odoo 来做交付。

我的逻辑很简单：**标品保底，个性增效，两者相加才是价值型项目。**

传统商业软件是买授权，你买了之后发现不合身，想改？对不起，定制费天价，甚至底层代码都不让你碰。出了问题，年年交服务费，还得看代理商脸色。

而开源 Odoo 的逻辑完全不同。它本身就有一整套成熟的标品模块（进销存、财务、考勤），底子非常稳。在此基础上，我可以用Python根据你的实际业务去做个性的定制开发。

最重要的一点是：**代码在手，心里不慌。** 你不用被任何厂商绑架。哪怕未来你不跟我合作了，这套系统依然是你的资产，别的程序员也能接手。

做IT这19年，我从珠三角的五金厂行政科做起，去过能源软件公司做PM，在大型制药企业扛过等保，在长三角机电工贸企业搞过0-1的数字化，现在又来到沙漠里做卫星物联和海外工厂ERP。我太清楚企业买系统时的那种“怕”了——怕钱花了打水漂，怕员工不用，怕项目烂尾。

不贪大求全、守住一期边界，比讲什么数字化转型的大词都管用。
